timeSeriesPreparation.internal.fail

Build, and by default throw, an error of the ported qc units.

Syntax

timeSeriesPreparation.internal.fail(unit, mnemonic, message, args...)
ME = timeSeriesPreparation.internal.fail(unit, mnemonic, message, args...)

Description

The port of NonGravForces.fail (0.12.0, 3cc0123) for the units of +qc, which raise every error through it (X-05). The identifier is timeSeriesPreparation:<unit>:<mnemonic>; the behaviour is otherwise that of the original: - the mnemonic starts with one of the classes input, dep, data, numeric, unsupported, notImplemented; - the message carries a correction hint after the marker " -> "; - without an output the exception is thrown from the caller's frame (throwAsCaller), so the stack points at the offending function; with an output it is returned and nothing is thrown.

Inputs

namesizetypedefaultdescription
unit1,1string—- Function name, e.g. "hampel".
mnemonic1,1string—- camelCase reason, first token from the classes above, e.g. "inputShape".
message1,1string—- sprintf format containing " -> ".
args1,:cell—- sprintf arguments of message, any number.

Outputs

namesizetypedefaultdescription
ME1,1MException—- Only when an output is requested.

Accuracy

Not applicable, because the function computes no number.

Errors

identifiercausecondition
timeSeriesPreparation:fail:inputMnemonicContractthe mnemonic does not start with one of the six classes.
timeSeriesPreparation:fail:inputHintContractthe message lacks the " -> " correction hint.

Example

Build the exception without throwing it.

ME = timeSeriesPreparation.internal.fail("hampel", "inputShape", ...
    "x must be KxM -> transpose the input");

Limitations

The identifiers it raises are built at run time, so the static audit cannot catalogue them; the ported units list them in their help until a conventions WP writes them out.
