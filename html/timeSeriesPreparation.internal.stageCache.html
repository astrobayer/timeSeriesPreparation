timeSeriesPreparation.internal.stageCache

A stage's outputs from the cache, or computed and stored.

Syntax

[outs, status] = timeSeriesPreparation.internal.stageCache(cacheDir, stage, key, nOut, compute)

Description

The stage cache of run (X-14, CONCEPT 6.6; owner decisions 2026-09-25). The outputs of a stage live in one MAT file per key, cacheDir/<stage>/<key>.mat, holding the variable outs (a 1 x nOut cell). The status says what happened, so a hit is never silent: "off" cacheDir is "": compute, store nothing; "hit" the file exists and loads: its outputs are returned, compute is not called; "miss" no file: compute, then store; "rewritten" the file exists but does not load, or holds no 1 x nOut cell outs: compute, then store over it; "unsaved" computed, but storing failed (e.g. no write access); the outputs are still returned. There is no eviction; the caller deletes the folder to clear it.

Inputs

namesizetypedefaultdescription
cacheDir1,1string—- Cache root; "" = off.
stage1,1string—- Stage name, a subfolder.
key1,1string—- Hex key (internal.contentHash).
nOut1,1double—- Outputs of compute, >= 1.
compute1,1function_handle—- () -> nOut outputs.

Outputs

namesizetypedefaultdescription
outs1,nOutcell—- The stage's outputs.
status1,1string—- "off", "hit", "miss", "rewritten" or "unsaved".

Accuracy

Exact: a hit returns what save stored (MAT-file version 7), bit for bit.

Errors

(none) The errors of compute propagate.

Example

The cache off: compute runs and nothing is stored.

[outs, status] = timeSeriesPreparation.internal.stageCache("", "demo", "0", 1, @() magic(3));

Limitations

No locking: two processes writing one key at the same moment may leave a file the next reader rewrites. Campaign mode (X-15) runs each arc once per key.
