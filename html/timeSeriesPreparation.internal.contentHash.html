timeSeriesPreparation.internal.contentHash

SHA-256 of the content of values, as 64 lowercase hex digits.

Syntax

h = timeSeriesPreparation.internal.contentHash(v1, v2, ...)

Description

The key of the stage cache (X-14, CONCEPT 6.6) is the SHA-256 of the stage, the toolbox version, the resolved settings and the input contents. This function feeds a canonical byte stream of its arguments to one SHA-256 (java.security.MessageDigest), so equal content gives equal keys on every machine and in every session: - numeric and logical arrays: class name, size, then the raw little-endian bytes (real part, then imaginary part); - char and string: size, then each element's UTF-8 bytes with its length (a missing string has its own tag); - struct: size, then per element each field name and value, in field order; - cell: size, then each cell; - table: its variable names, then each variable; - datetime: its time zone and the POSIX seconds. Objects are refused: this L0 helper knows no class of the package (CONCEPT 3.2). run hashes an Arc as a struct of its content (t, obs, names, units, weights, layers, filled), leaving out the provenance, which carries creation times. Every value starts with a type tag, so [1 2] and "12" or a struct and a cell never share a stream. A function handle refuses: what it computes cannot be read from it (func2str misses captured variables and the code of named functions).

Accuracy

Exact: the SHA-256 of the canonical bytes. The stream is specified above so it can be rebuilt elsewhere. A Python rebuild (hashlib, 2026-09-25) gives, and TestStageCache pins: contentHash(uint8('abc')) = 40227623b648a612552d1d3ee04c07d5013520f932d94327a12d1b2554717715 contentHash("qc", struct("hampelWindow", 61)) = 5bdcf53a514ff0c8eeba0139dc6c1bfbcc3125d4aa8ad79ea3b8a8b19310fc93 The tag of a value is its type name in UTF-8, a zero byte and its size as little-endian doubles; a string element is prefixed by its byte count as a tagged double.

Example

Two equal settings structs give one key; a changed field another.

a = timeSeriesPreparation.internal.contentHash("qc", struct("hampelWindow", 61));
b = timeSeriesPreparation.internal.contentHash("qc", struct("hampelWindow", 31));

Limitations

Field order matters: struct("a", 1, "b", 2) and struct("b", 2, "a", 1) hash differently. The callers build their settings in a fixed order.
