timeSeriesPreparation.internal.requirePackage

Refuse at the point of use when an optional dependency is missing.

Syntax

timeSeriesPreparation.internal.requirePackage(name, caller)

Description

gracefoReading is an optional dependency (CONCEPT 3.1): only the L1B-specific functions call it, and the sigtools half runs in base MATLAB. A function that needs it calls this first, so a missing reader fails by name at the point of use, not as "Unable to resolve the name" somewhere deeper. The layering test (tests/TestLayering.m) demands this call in every package file that references gracefoReading.

Inputs

namesizetypedefaultdescription
name1,1string—- Namespace that must resolve, for example "gracefoReading".
caller1,1string—- Name of the calling function, without the package prefix; it becomes the middle part of the identifier.

Outputs

(none)

Accuracy

Not applicable, because the function computes no number. It decides presence only: a namespace resolves when meta.package.fromName finds it on the current path. It does not check a minimum version.

Errors

None of its own. When name does not resolve it raises timeSeriesPreparation:<caller>:depMissing on the caller's behalf, and the caller documents that identifier under its own ERRORS, where a user looks it up. An invalid name or caller is refused by the arguments block with a MATLAB: identifier.

Example

The toolbox itself always resolves, so this passes silently.

timeSeriesPreparation.internal.requirePackage("timeSeriesPreparation", "example");

Limitations

Presence only. A dependency present in a version too old for the caller passes here and fails later; minimum versions are the release's dependency table (GUIDE section 3).
